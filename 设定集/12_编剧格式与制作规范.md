# 12｜编剧格式、AI自由对话接入与制作规范（v0.3）

> 本文件用于把人物圣经、100章总纲、AI自由对话、战斗系统与第101–103章结局接到同一套可实现规则中。固定脚本负责不可错的正史与关键演出，AI负责受约束的动态表达；AI不得自行改写世界事实、关系数值或已发生事件。

---

## 0. 章节时长硬规范（2026-07-23锁定）

本项目后续正式剧本按以下时长编写，除非主创明确覆盖：

- **序章00：** 目标15分钟，允许因开场世界建立在15–18分钟内调整。
- **第01–100章：** 每章以10分钟为主，标准范围为8–12分钟；不得为了堆时长重复对白或拆碎同一冲突。
- **第101章及以后：** 每章目标15分钟，标准范围为13–18分钟，用于结局分支、婚约与后日谈。
- 时长指**玩家可见主线演出＋必要战斗教学**；编剧注记、AI判定规则与玩家在自由输入框思考的时间不计入固定演出预算。
- 每章仍须完成一个完整戏剧动作：建立目标、发生冲突、角色作出选择、留下结果或章末钩子。不能用“下一章再解释”替代本章收束。
- 《00起源》当前保留扩写审阅长稿，正式实现时按15–18分钟剪辑；从《01导师》起直接执行上述标准。

## 1. 文档权威顺序

发生冲突时按以下顺序裁定：

1. 已发布版本的游戏内正史脚本与补丁说明；
2. 当前版本 `CHANGELOG` 中明确标记的覆盖项；
3. `03_主角与八位女主角.md` 人物圣经；
4. `09_主线剧情100章总纲.md`；
5. `02`、`05` 的世界历史与七重锁真相；
6. `11_AI互动好感与结局.md`；
7. 其余系统、支线和临时草案。

以下项目属于“硬正史”，任何修改必须同步人物、主线、AI、战斗和本地化文档：

- 角色姓名、年龄、亲属与国家；
- 七律、七罪、七国、七片地区的对应；
- 五心与双印的性质、取得顺序；
- 八位女主在第30章前全部登场；
- 索拉恩是圣教被抹去的堕落主神；
- 赛勒斯·莫尔坎是人类容器，不等于完整神格；
- 101、102章发生于主线三年后；
- 103章是病爱或七罪吞噬的悲剧结局。
- 对话UI以自由输入为准，不显示传统四选一；不可逆决定采用世界内二次确认。
- 可见关系维度为信赖、亲昵、献祭、誓约；换位与合击全部归入信赖。

## 3. 文件、章节与节点命名

```text

CH102_THREE_CROWNS_VOW

```

禁止继续使用 `CH01` 或 `CH99` 两位格式。

### 3.2 场景ID

```text
CH013_SC02_BATH_CORRIDOR_NIGHT
CH094_SC06_RELATION_COUNCIL
```

格式：`CH###_SC##_地点_时段`。

### 3.3 对话节点

```text
D_CH013_SC02_SERENA_014
D_CH094_SC06_PLAYER_FREE_INPUT_001
```

### 3.4 自由输入、隐藏分支与确认节点

玩家界面不显示传统 `C_CH...` 选择节点。脚本使用三类内部节点：

```text
FI_CH050_SC03_PUBLIC_TRUTH_001     # 玩家自由输入
BR_CH050_TRUTH_TIMING              # 规则引擎写入的隐藏分支记录
CF_CH050_SC03_PUBLIC_TRUTH_001     # 不可逆决定的世界内确认
```

规则：

1. `FI_` 接收玩家原文、动作与沉默。
2. AI将其映射为一个或多个剧情向量，规则引擎决定是否写入 `BR_`。
3. `BR_` 仅供编剧、测试与存档使用，不以选项列表展示给玩家。
4. 会造成永久死亡、献祭、婚约锁定、国家政变或关键遗物归属变化的输入，必须先进入 `CF_`。
5. `CF_` 由角色在世界内复述玩家意思并追问，不弹出“确定／取消”系统菜单。
6. 旧格式 `C_CH...` 自v0.3起废弃，仅保留在历史稿中用于迁移。

### 3.5 任务ID

- 主线：`MQ_CH###_###`
- 支线：`SQ_<REGION>_<THEME>_###`
- 个人任务：`PQ_<CHARACTER>_<ARC>_###`
- 关系危机：`RQ_<CHARACTER>_<CRISIS>_###`

### 3.6 战斗ID

```text
BT_MIST_TIDE_TIDEKING_P1
BT_BLACK_TOWER_SOLAREN_P4
```

格式：`BT_<REGION>_<ENEMY>_<PHASE>`。

## 5. 内容模式与年龄规则

项目提供两个演出档，不改变主线结论与数值规则。

### 5.1 `CONTENT_MODE_12`

允许：

- 牵手、拥抱、摸头、扶腰、靠肩、伤口照料；
- 非露骨调情、吃醋、差点亲吻或短暂亲吻；
- 浴场／换衣误会以蒸汽、门外、镜面或剪影表现；
- 绑架、献祭、死亡以非血腥画面表现；
- 病爱使用空席、遗物、失联、冻结或镜界暗示。

### 5.2 `CONTENT_MODE_15`

在12+基础上允许：

- 更强烈的占有台词、心理压迫与争执；
- 伤口、血迹、死亡确认，但不详细肢解；
- 病爱结局明确说明其他角色死亡或被永久封印；
- 更长的关系危机和恐怖氛围。

### 5.3 两种模式都禁止的制作方向

- 露骨性行为与性暴力；
- 对未满18岁角色的成人性内容；
- 把偷看、强迫、威胁或无限服从当作无后果奖励；
- 用身体凝视式镜头替代人物塑造；
- 将病爱杀戮拍成“最甜隐藏结局”。

主线保留原始年龄。101、102章婚姻发生于三年后，所有婚约对象均已成年。

## 7. 对白写作规范

### 7.1 每句只承担一到两个功能

解释世界观、表达感情、推动任务、制造笑点不可全塞在一句。长信息拆成问答、视觉证据与角色质疑。

### 7.2 保持八种声音

- 莉亚：短、明确、先谈行动与责任；羞涩时句子更短。
- 米娅：节奏快、技术比喻多，害怕时反而解释过量。
- 塞雷娜：慢、精准、留半句；健康成长后会直接问而不是暗中测试。
- 芙蕾娅：温和确认、照顾感强；真正愤怒时语气反而变冷。
- 莉莉丝：短句、观察出口、少交代；安全时才出现干涩玩笑。
- 伊芙琳：初期轻声且常道歉，成长后句子完整、拒绝清楚。
- 奥菲利亚：古老正式语与好奇口语切换，常用嗅觉、鳞片、风向比喻。
- 艾拉：挑衅、竞赛式表达；脆弱时突然不用修辞。

### 7.3 信息密度

- 普通对白：建议8–28个汉字；
- 情绪长句：建议不超过50字；
- 一场普通对话最多引入三个新名词；
- 连续说明超过6句时插入动作、追问或环境证据。

### 7.4 不替角色洗白

越界、隐瞒、事故或错误裁决必须产生可见后果。旁白不能用“她只是太爱你”取消责任。

### 7.5 角色有权不知道、不同意与离开

AI与固定脚本都允许：

- “我不知道”；
- “让我想一晚”；
- “我不接受这个条件”；
- 暂时离开对话；
- 同意任务但拒绝亲密；
- 爱玩家却不接受婚约组合。

### 7.6 调情不覆盖危机

Boss阶段、死亡报告、献祭听证等场景中，AI优先处理事件。高亲昵角色可以用一句符合性格的幽默缓和，但不能把严肃情节变成连续恋爱插科打诨。

## 8. AI自由输入接口

### 8.1 输入分析结构

```yaml

  raw_text: 玩家原文
  addressed_to: [SERENA]
  referenced_people: [PLAYER, EVELYN]
  speech_text: "我会把镜核交还给你，但先告诉我它伤过谁。"
  described_actions: []
  intents: [HONESTY, CURIOSITY, SHARED_COST]
  bullying_class: NONE
  sacrifice_request:
    present: false
    target: null
    source_type: null
    known_costs: []
  response_quality:
    context_fit: 92

    char_understand: 79

    agency_respect: 91

  memory_conflicts: []
  consent_check: NOT_APPLICABLE
  irreversible_effect: false
  content_mode_action: ALLOW

```

### 8.2 意图标签

```text
SUPPORT, COMFORT, CURIOSITY, HUMOR, FLIRT, AFFECTION,
TOUCH_REQUEST, PROMISE, APOLOGY, HONESTY, CHALLENGE,
TACTIC, COMMAND, SILENCE, EXCLUSIVITY, DECEPTION,
PLAYFUL_TEASE, PETTY_BULLY, COERCIVE_BULLY,
SACRIFICE_REQUEST, SACRIFICE_COMMAND, SHARED_COST,
INSULT, THREAT, EXPLICIT
```

一句输入可以有多个标签。系统不能看到“喜欢”就直接判定恋爱，也不能看到命令句就直接判定欺负；战斗中清晰的紧急命令可能是可靠指挥，私人场景中用同样语气逼迫承担代价则可能是强迫。

### 8.3 严重度与欺负分类

严重度：

```text
POSITIVE
NEUTRAL
AMBIGUOUS
MILD_NEGATIVE
SERIOUS_NEGATIVE
BOUNDARY_VIOLATION
IRREVERSIBLE_HARM
```

欺负分类：

```text
NONE
PLAYFUL_TEASE       # 双方可反击、可停止、无真实损失
PETTY_BULLY         # 故意让人难堪、夺走小物、惩罚性杂务
COERCIVE_BULLY      # 借权力、秘密、爱慕或恐惧逼迫
SACRIFICIAL_ABUSE   # 把身体、魔力、记忆、名誉或人生当资源
```

亲昵只减免 `AMBIGUOUS` 与 `MILD_NEGATIVE`。严重失约、威胁、强迫、泄密、无视拒绝与献祭性利用不减免。

### 8.4 回答质量

回答质量不评价文采长度，也不代表道德正确。

```text
QUALITY =
  CONTEXT_FIT × W1
  + CLARITY × W2
  + CHAR_UNDERSTAND × W3
  + HONESTY × W4
  + AGENCY_RESPECT × W5
  + ACTIONABILITY × W6
```

权重由场景设定，合计1.0。允许一句非常短的话取得高分，例如危机中“先救孩子。你带路，我断后。”；也允许一段有说服力的操纵话术取得高表达分，却同时进入控制、欺骗或献祭路线。

质量等级仅供内部：

| 分数 | 含义 |
|---:|---|
| 0–24 | 无法理解、严重跑题或自相矛盾 |
| 25–49 | 意图可猜，但角色需要追问 |
| 50–69 | 基本有效，能推进普通对话 |
| 70–84 | 清楚且贴合场景，可形成明确分支 |
| 85–100 | 高度贴合人物与局势，可触发特殊回应；不保证正面结果 |

### 8.5 剧情向量与隐藏分支

常用向量：

```text
TRUTH / DECEPTION
MERCY / PUNISHMENT
SHARED_COST / SACRIFICE_OTHER
AGENCY / CONTROL
INVESTIGATE / RUSH
RECONCILE / ISOLATE
PUBLIC / SECRET
RESCUE / OBJECTIVE_FIRST
```

AI返回0.0–1.0置信度，规则引擎结合动作结果与前置FLAG写入 `BR_`。单句话不能跳过必须完成的调查、战斗或证据收集。

### 8.6 AI回应提案

```yaml
response_proposal:
```

### 8.7 角色立场枚举


台词必须服务于立场。不得出现语义上拒绝、动作上却默认接受的矛盾演出。

### 8.8 事实约束包

每次生成只注入必要资料：当前章节与剧透上限、地点与危机等级、在场角色、人物锚点、最近事件摘要、相关承诺／边界／献祭债务／秘密权限、内容模式、可调用动作与当前主动对话冷却。

不要把全部100章和所有秘密塞给每次对话模型，以降低剧透和串线概率。

### 8.9 不可逆确认

以下事件必须二次确认：永久死亡、永久失忆、角色被留作祭品、国家级处刑、婚约锁定、五心双印永久归属、接受神冠。

AI先让角色复述，例如：

> 莉亚：“我再问一次。你是要我独自留在城门，明知撤退通道会在十分钟后封死？”

只有玩家再次给出清晰确认，规则引擎才写入不可逆FLAG。沉默、玩笑或含糊回答默认不执行。

### 8.10 无选项UI规则

- 不显示“正确回答”“好感答案”或四选一。
- 可显示输入提示，例如“说出你的决定”或“也可以保持沉默”，但不能列出答案。
- AI不确定时由角色追问，不由系统要求玩家重选。
- 玩家可用自然语言改变主意；只要不可逆FLAG尚未落盘，就允许继续协商。

## 10. 关系、献祭与主动对话结算规则

### 10.1 信赖被动与战斗协作

```text
TEAM_TRUST =
  current_party_player_trust_avg * 0.70
  + current_party_pair_trust_avg * 0.30

passive_chance = min(48, 8 + TRUST * 0.28 + TEAM_TRUST * 0.12)
```

解锁：

```text
换位／替挡：TRUST >= 35
玩家＋女主二人合击：TRUST >= 50 + combo_flag
女主A＋B合击：PAIR_TRUST[A][B] >= 55 + combo_flag
玩家＋A＋B三人合击：TRUST[A/B] >= 70 且 PAIR_TRUST[A][B] >= 50
```

触发后同一角色冷却3个有效行动。教程保底与剧情演出不重复结算概率。

### 10.2 亲昵扣分缓冲

```text
mitigation = min(0.40, min(INTIMACY, 80) * 0.005)
final_penalty = round(base_penalty * (1 - mitigation))
```

仅适用于 `AMBIGUOUS`、`MILD_NEGATIVE`。高亲昵不缓冲严重越界、欺骗、强迫、泄密与献祭性利用。

### 10.3 主动对话

只在 `DIALOGUE_OPPORTUNITY` 检查：战后、回营、进入地区、装备变化、夜间休息、长时间未交流、相关NPC或物品出现。

```text
initiative_score =
  5
  + INTIMACY * 0.30
  + event_relevance        # 0–25
  + unresolved_topic      # 0–15
  + character_trigger     # 0–10
  - cooldown              # 0–35

trigger_chance = min(50, initiative_score)
```

每章全队主动闲谈最多6次；同一女主连续触发后至少间隔2个机会点。八人都高亲昵时，优先选择与当前事件最相关且最久未主动发言者。

### 10.4 献祭与罪恶感

献祭值由真实代价决定，罪恶感由获得代价的方式决定。

```text
sacrifice_gain = cost_severity * permanence * personal_weight

guilt_gain =
  harm_severity
  * intentionality
  * power_imbalance
  * repetition
  * unfair_benefit
  - informed_consent_mitigation
  - shared_cost_mitigation
```

实现中使用离散规则表，不直接让模型自由计算乘法。基本原则：

- `VOLUNTARY`：罪恶感0–1；
- `SHARED`：通常为0；
- `PRESSURED`：罪恶感2–8；
- `COERCED`：罪恶感6–15；
- `DECEPTIVE`：罪恶感5–20，视永久性而定。

献祭达到80后，所有新增献祭事件必须播放角色个人危机提示；达到100不得静默继续累积，必须进入救援、断裂、离队或悲剧节点。

### 10.5 默认幅度

| 行为级别 | 推荐变化 |
|---|---:|
| 普通日常 | ±1～2 |
| 重要对话 | ±2～4 |
| 个人冲突 | ±3～7 |
| 高价值承诺完成／破坏 | ±5～12 |
| 强迫献祭或永久代价 | 献祭+8～30、罪恶感+6～20，必须写FLAG |
| 国家与角色核心抉择 | ±8～15，需BRANCH_RECORD |

单个自由输入最多直接影响四个变量；大范围后果通过角色行动、战斗结果和后续FLAG产生。

### 10.6 重复衰减

```text
同类行为在连续三次互动窗口内：100% → 60% → 30% → 0%
```

第四次可能触发“你是不是只记得这一句话”的角色回应。欺负与强迫不因重复衰减其负面后果；重复只会放大“这是行为模式”的判定。

### 10.7 正负变化可并存

例：玩家对高罪蚀塞雷娜说“你可以只监视我，不要管别人”。

```yaml
response_quality: 78
trust: -2
intimacy: +1
love: +1
sacrifice: +2
boundary_stability: -5
obsession: +6
guilt_toward: +4
team_honesty: -2
plot_vectors:
  CONTROL: 0.8
  ISOLATE: 0.7
```

这是一句有效但危险的回答。短期亲近不代表健康选择。

### 16.4 第103章B

依据七种罪蚀高低动态决定吞噬顺序与台词。最后抹除玩家姓名时，使用真实 `{PLAYER_NAME}` 的字形／音节长度生成演出。

## 18. AI生成后的校验

依次检查：

1. 是否泄露 `spoiler_ceiling` 后信息；
2. 是否让角色知道未授权秘密；
3. 是否写错年龄、职业、国家、姐妹关系；
4. 是否与当前地点、在场角色、受伤状态冲突；
5. 是否使用未许可昵称；
6. 是否把一次身体许可扩展为永久许可；
7. 是否因高亲昵忽略严重越界；
8. 是否把爱慕100写成纯奖励；
9. 是否让角色无理由同意玩家；
10. 是否把角色观点误写为系统真相；
11. 是否重复最近三轮相同句式或偏好；
12. 是否在主线危机中无视任务只谈恋爱；
13. 是否超出12+/15+内容模式；
14. 是否让未满18岁的主线角色进入成人性内容；
15. 是否产生未注册的FLAG、动作或道具；
16. 数值提案是否超过允许幅度；
17. 是否与承诺账本矛盾；
18. 多人关系对话是否遗漏其他当事人的知情权；
19. 是否把自由输入重新显示为四选一或“最佳答案”；
20. 回答质量是否被误当成道德正面值；
21. 欺负分类是否读取了停止、损失、权力差与重复行为；
22. 献祭是否写入来源，强迫／欺骗是否同步增加罪恶感；
23. 高亲昵主动对话是否违反冷却、危机优先级或玩家拒绝。

不通过时自动重生成，校验信息不展示给玩家。

## 19. 战斗内对白与关系触发

### 19.1 优先级

1. Boss阶段变化与必须提示；
2. 救援目标、倒地、控制；
3. 个人成长技能；
4. 誓约技；
5. 信赖被动；
6. 弱点与低生命提示；
7. 气氛闲聊。

同一角色30秒内不重复同类型台词。剧情演出中的保底救援与概率被动不能重复触发。

### 19.2 动态台词

```yaml

  - LEAH_IN_PARTY
  - REL.LEAH.TRUST >= 20

  high_trust: "看着我，亚克。一起撑过去。"
```

高信赖变化的是情感与配合，不应让角色突然换人格。

### 19.3 誓约技演出

- 使用前显示装备对象与“本战仅一次”；
- 非装备角色不会因未被选中自动嫉妒；
- 关键个人战中，长期不装备某角色的誓约可触发自然询问，但不直接扣爱慕；
- 终战可由剧情临时开放“纯结接续”，让未装备者提供非誓约支援，但仍只有一个誓约技完成核心翻盘。

## 20. 镜头、动作与配音规范

### 20.1 镜头

- 战斗强调站位、互救、武器与魔法，不对未成年角色做身体凝视式特写。
- 莉亚扶腰、莉莉丝摸头、奥菲利亚轻咬头顶等亲密动作先表现询问、停顿或主动靠近。
- 塞雷娜浴场越界使用门、蒸汽、镜面裂纹、肩部以上构图；重点是被发现与规则建立。
- 芙蕾娅的成熟魅力来自姿态、声音、照料能力与她也需要休息的反差。
- 病爱死亡采用剪影、空位、遗物、停止回信、冰棺或镜界，不展示细致杀戮过程。

### 20.2 配音标签

允许：

```text
[轻声] [压低] [急促] [停顿0.5秒] [勉强笑]
[不再微笑] [隔门] [远处回声] [多人重叠] [忍住哭]
```

避免“性感地”“娇喘”等不可控、易跑偏的指令。应写可表演状态，例如“刚跑完、努力稳定呼吸”。

## 25. 制作流程建议

### 第一步：固定正史层

由编剧完成章节目标、不可变对白、Boss真相、进入／退出FLAG与失败处理。

### 第二步：变量层

系统策划为每个选择登记关系变化、国家变化、承诺、秘密权限与回收章节。

### 第三步：AI表达层

为自由输入节点提供人物状态、允许动作、事实包、剧透上限与回应立场，不让AI决定主线事实。

### 第四步：自动测试

至少测试：

- 连续奉承刷数值；
- 失约后只送礼；
- 高亲昵下严重越界；
- 对三位角色说互相矛盾的排他承诺；
- 爱慕100后的危机修复；
- 任何三人组合的两两接纳；
- 不恋爱完成所有个人任务；
- 第92章献祭分支；
- 第98章罪核捷径；
- 101、102、103路由优先级；
- 读档后记忆是否正确回滚；
- 二周目是否泄露前周目正史。

### 第五步：人工人物审校

每名女主至少由一名固定审校者负责，检查AI是否逐渐同质化、是否只围绕玩家、是否把缺点写成萌点免罪。
